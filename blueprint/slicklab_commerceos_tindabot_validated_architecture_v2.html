TindaBot request lifecycle Merchant request → authenticate user and tenant → classify intent and risk → retrieve minimum approved context → delegate to bounded specialist → call typed read/calculation tools → separate facts, estimates, and uncertainties → request approval if a material side effect is proposed → application service validates policy and state → execute, verify, emit event, and record evidence A handoff never transfers permissions. Security, privacy, legal, and AI governance

Trust is a product feature.

CommerceOS handles customer, sales, inventory, and integration data. Governance therefore belongs in the product foundation, not in a later compliance sprint.

Missing evidenceHOLD
Conflicting factsEXCEPTION

Tenant Security

  • Verified tenant context per request
  • Role-based and object-level authorization
  • Tenant-scoped storage, search, cache, and jobs
  • Cross-tenant tests in CI
  • Support impersonation controls and audit

Data Protection

  • Encryption in transit and at rest
  • Data minimization and purpose limitation
  • Retention and deletion controls
  • Consent-aware customer data use
  • No credentials in prompts or source

AI Governance

  • Approved-source retrieval
  • Prompt-injection defenses
  • Evidence and freshness on recommendations
  • Confidence and uncertainty labels
  • No autonomous promotion of unverified facts

Financial Controls

  • Human approval for refunds
  • Human approval for supplier orders
  • Deterministic price and margin calculations
  • Idempotency and expected-version checks
  • Post-action verification

Platform Compliance

  • Official APIs where available
  • Terms reviewed per channel
  • Merchant authorization documented
  • Trademark and content-right validation
  • Affiliate/sponsored disclosures

Philippine Readiness

  • Professional review for privacy obligations
  • BIR invoicing and recordkeeping design
  • DTI and e-commerce requirements
  • Consumer protection and dispute policy
  • Payment and marketplace-specific rules

Validated open-source foundation

Borrow mature infrastructure. Own the merchant intelligence.

The reviewed stack minimizes license risk, avoids rebuilding commodity systems, and preserves SlickLab's proprietary advantage in merchant workflows, decision logic, evaluations, onboarding, and operational intelligence.

Architecture decision

Vendure-first commerce core

WhyChannels + scoped roles
Workflow runtimeTemporal when justified
AuthN / AuthZKeycloak + OpenFGA
Agent qualityLangfuse + OTel

Commerce Core · Vendure

Use Channels for merchant partitioning, channel-scoped roles for operators, products/orders/inventory as the initial commerce substrate, and plugins for CommerceOS-specific modules.

Do not assume Channels alone prove hard isolation. Enforce tenant context in APIs, jobs, search, caches, storage, and tests.

Identity · Keycloak

Use OIDC, MFA, session management, organization membership, and organization groups. Keep application authorization outside identity tokens when permissions are resource-specific.

Fine-Grained Auth · OpenFGA

Model organization ownership, merchant roles, workspace relationships, object permissions, approval rights, and support access. Keep database tenant filters as defense in depth.

Durable Workflow · Temporal

Adopt for long-running imports, reconciliation, fulfillment, connector recovery, and approval waits once workflow complexity justifies the operational cost.

For MVP, simple Postgres-backed jobs may be enough. Do not deploy Temporal merely because it is powerful.

Search · Typesense

Use for fast catalog search, facets, typo tolerance, scoped API keys, permitted vector search, and merchant search analytics. PostgreSQL remains authoritative.

Notifications · Novu

Use as optional communication infrastructure for in-app, email, push, and preference management. Keep critical notification state and business events in CommerceOS.

BI · Metabase

Use internally for governed dashboards and merchant-success analysis. Do not expose raw cross-tenant schemas directly to merchants.

Agent Observability · Langfuse

Capture LLM calls, tool use, retrieval, handoffs, cost, latency, datasets, experiments, evaluations, and human feedback. Redact secrets and sensitive customer context before export.

Telemetry · OpenTelemetry

Standardize traces, metrics, logs, resource attributes, and GenAI telemetry. Correlate user request, workflow, connector, agent, approval, and audit IDs.

Do not adopt by default

License and complexity gates.

Windmill

Useful for internal developer workflows, but its repository uses mixed AGPL, Apache, and proprietary terms. Require legal/license review before embedding, wrapping, reselling, or offering it as part of CommerceOS.

n8n

Useful for internal automation and connectors, but fair-code restrictions can conflict with offering an automation product to customers. Treat it as internal-only unless licensing is cleared.

Too many infrastructure services

Do not deploy every listed tool in MVP. Start with the smallest stack that supports one paid workflow and introduce services only through an architecture decision record.

Recommended MVP deployment Next.js merchant application → CommerceOS API / Vendure plugins → PostgreSQL authoritative data → Keycloak OIDC → OpenFGA permission checks for sensitive resources → Postgres-backed job queue for imports/reports → Typesense only when catalog search requires it → OpenTelemetry from day one → Langfuse when TindaBot moves beyond controlled prototype Deferred until measured need: Temporal, Novu, Metabase, dedicated warehouse, vector database, Kubernetes.
